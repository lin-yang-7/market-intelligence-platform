# Event Driven Architecture

Version: 1.0

Status: Approved

------------------------------------------------------------------------

# 1. Purpose

This document defines the event-driven architecture of the Market
Intelligence Platform.

Apache Kafka is the core event communication layer between services.

The event system provides:

-   Real-time processing
-   Service decoupling
-   High throughput
-   Fault tolerance
-   Event replay capability

------------------------------------------------------------------------

# 2. Event Architecture Overview

    Exchange

       |

    Collector Service

       |

    Kafka Cluster

       |

    +----------------+
    |                |
    Feature Service  Market Service

    Rule Service     Signal Service

    Alert Service    WebSocket Service

------------------------------------------------------------------------

# 3. Kafka Responsibilities

Kafka provides:

-   Event transport
-   Message persistence
-   Consumer management
-   Event replay
-   Service decoupling

Kafka is not used as permanent business storage.

Historical data is stored in ClickHouse.

Business data is stored in MySQL.

# 7. Event Schema Standard

Every event must contain:

``` json
{
  "event_id": "",
  "event_type": "",
  "version": "1.0",
  "timestamp": "",
  "source": "",
  "payload": {}
}
```

------------------------------------------------------------------------

# 8. Producer Rules

Producers must:

-   Generate unique event IDs
-   Include schema version
-   Validate payload
-   Handle publish failures
-   Support retries

------------------------------------------------------------------------

# 9. Consumer Rules

Consumers must:

-   Be idempotent
-   Track offsets
-   Handle duplicate messages
-   Support retry
-   Provide monitoring metrics

------------------------------------------------------------------------

# 10. Reliability Design

## Retry Mechanism

Temporary failures use retry queues.

------------------------------------------------------------------------

## Dead Letter Queue

Failed messages are moved to:

    DLQ.<topic>

for investigation.

------------------------------------------------------------------------

## Replay

Kafka retention allows:

-   Historical replay
-   Service recovery
-   Data reprocessing

------------------------------------------------------------------------

# 11. Ordering Guarantee

Ordering is guaranteed within the same partition.

Partition key:

    exchange + symbol

Example:

    binance.BTCUSDT

ensures symbol events remain ordered.

------------------------------------------------------------------------

# 12. Consumer Groups

Examples:

Market consumers:

    market-service-group

Feature consumers:

    feature-service-group

Signal consumers:

    signal-service-group

Each business function has independent consumption.

------------------------------------------------------------------------

# 13. Event Monitoring

Monitor:

-   Consumer lag

-   Error rate
-   Retry count

Metrics exported to Prometheus.
